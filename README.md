# Movie Rating Analysis

An end-to-end MovieLens 20M project using PySpark for aggregation, Cassandra for the complete raw ratings data and analysis summaries, and Matplotlib for charts.

## Project files

```text
movie-rating-analysis/
├── analysis.py
├── app.py                  # Streamlit presentation dashboard
├── cassandra_schema.cql
├── data/
│   ├── movie.csv
│   └── rating.csv
├── output/                 # generated by analysis.py
│   ├── charts/
│   └── tables/
├── requirements.txt
└── README.md
```

## Streamlit presentation dashboard

The dashboard reads the four Spark summary CSVs already written under `output/tables/`. It shows top-rated movies, average rating by genre, the rating distribution, and average rating by movie release year. Search, genre, year, and minimum-rating-count controls help focus the presentation. Missing summary files are reported in the relevant chart area; the app does not fabricate values.

Run it from the project folder using the existing Python 3.11 environment:

```bash
cd ~/movie-rating-analysis
.venv/bin/python3.11 -m pip install -r requirements.txt
.venv/bin/python3.11 -m streamlit run app.py
```

Open the local URL printed in Terminal (usually `http://localhost:8501`). The default source is `output/tables/`. You can select a different folder in the sidebar, upload summary CSVs, or choose Cassandra. The upload filenames should be `movie_stats.csv`, `genre_stats.csv`, `rating_distribution.csv`, and `yearly_stats.csv`.

For Cassandra, start the project container and schema as described below, then choose **Cassandra** in the app. Defaults are host `127.0.0.1`, port `9042`, keyspace `movie_analysis`. Override them before launch if needed:

```bash
export CASSANDRA_HOST="127.0.0.1"
export CASSANDRA_PORT="9042"
export CASSANDRA_KEYSPACE="movie_analysis"
.venv/bin/python3.11 -m streamlit run app.py
```

The Cassandra view loads only the four summary tables and limits each read to 100,000 rows by default (configurable with `CASSANDRA_ROW_LIMIT`, capped at 500,000). It does not read all 20 million raw ratings into the dashboard.

## Prerequisites

- macOS on Apple silicon
- Python 3.11
- Java 17
- Docker Desktop with the Cassandra container running and port 9042 available
- MovieLens 20M CSV files at `data/movie.csv` and `data/rating.csv`

The repository already contains a `.venv`. Its `python` and `python3` links have been corrected to use the configured Python 3.11 interpreter.

## Run

From this project folder:

1. Install the Python dependencies into the project environment:

   ```bash
   .venv/bin/python3.11 -m pip install -r requirements.txt
   ```

2. Start the existing Cassandra container and apply the schema:

   ```bash
   docker start movie-cassandra
   docker cp cassandra_schema.cql movie-cassandra:/tmp/cassandra_schema.cql
   docker exec movie-cassandra cqlsh -f /tmp/cassandra_schema.cql
   ```

   `cassandra_schema.cql` creates `movie_analysis`, the raw `rating_records` table, and four analysis summary tables.

3. Run the complete analysis:

   ```bash
   .venv/bin/python3.11 analysis.py
   ```

   The script streams every row from `data/rating.csv` into Cassandra's `rating_records` table, then loads the four summary tables. It writes four aggregate CSVs under `output/tables/`, three charts under `output/charts/`, and compares Cassandra row counts against the submitted source rows and generated summaries. The raw ratings import uses bounded concurrent requests, so the 20-million-row dataset is not collected into memory. If an import is interrupted, rerunning the script upserts rows using `(user_id, movie_id)` as the primary key. It defaults to Cassandra at `127.0.0.1:9042`.

4. To generate and inspect CSVs and charts before Cassandra is available:

   ```bash
   .venv/bin/python3.11 analysis.py --skip-cassandra
   ```

## Analysis tables

| Cassandra table | Stored data |
| --- | --- |
| `rating_records` | Every raw MovieLens rating: user, movie, rating, and original timestamp text; one row per user/movie pair |

The remaining Cassandra tables contain aggregates and are intentionally much smaller than the source dataset:

| Cassandra table | Summary grain |
| --- | --- |
| `movie_stats` | One row per movie: title, genres, average rating, and number of ratings |
| `genre_stats` | One row per genre: average rating and rating count across movies with that genre |
| `rating_distribution` | One row per rating value: number of ratings |
| `yearly_stats` | One row per parsed release year: average rating and rating count |

The same aggregates are exported as CSV files. `yearly_stats` excludes titles without a four-digit release year; `genre_stats` excludes `(no genres listed)`. Genre counts include a rating once for each genre assigned to its movie. The raw table preserves the source timestamp as text so its original value is retained.
